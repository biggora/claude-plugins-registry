# Loading and Error Boundaries

## Loading UI

A `loading.tsx` file provides route-segment loading UI and automatically wraps the page below it in Suspense. Prefer a skeleton that preserves the destination's layout and communicates what is pending.

```tsx
// app/dashboard/loading.tsx
export default function Loading() {
  return <DashboardSkeleton />
}
```

For finer control, place `<Suspense>` around the smallest slow or request-time region. Under Cache Components and Partial Prefetching, these fallbacks can become part of the route's click-time App Shell.

## Route-Segment Errors

`error.tsx` is a Client Component. In Next.js 16.3, prefer the stable `retry()` prop because it re-fetches and re-renders the boundary's children. `reset()` only clears client error state and re-renders without re-fetching, so it often cannot recover from a Server Component failure.

```tsx
'use client'

import { useEffect } from 'react'

export default function ErrorPage({
  error,
  retry,
}: {
  error: Error & { digest?: string }
  retry: () => void
}) {
  useEffect(() => {
    reportError(error)
  }, [error])

  return (
    <div>
      <h2>Something went wrong</h2>
      <button onClick={retry}>Try again</button>
    </div>
  )
}
```

Do not show raw Server Component error messages in production. Next.js replaces them with a generic message and digest to avoid leaking sensitive details; correlate the digest with server logs.

Errors bubble to the nearest parent boundary. Re-throw during render only when a parent owns the correct recovery UI. Error boundaries do not catch ordinary event-handler errors; handle those in the event flow.

## Component-Level Recovery With `catchError`

Use stable `catchError` from `next/error` when recovery belongs around a component subtree rather than an entire route segment. It correctly lets `redirect()` and `notFound()` pass through and clears error state on navigation.

```tsx
'use client'

import { catchError, type ErrorInfo } from 'next/error'

function ErrorFallback(
  props: { title: string },
  { error, retry }: ErrorInfo
) {
  return (
    <section>
      <h2>{props.title}</h2>
      <p>{error.message}</p>
      <button onClick={retry}>Try again</button>
    </section>
  )
}

export default catchError(ErrorFallback)
```

Do not wrap the default export of `error.tsx` with `catchError`; Next.js already supplies that route boundary.

## Global Errors

Use root `app/global-error.tsx` for failures in the root layout or template. It replaces the root document, so it must render its own `<html>` and `<body>` and include any critical styling or theme state it needs.

## Expected Errors and Not Found

Model expected failures such as validation or unavailable data as return values or rendered states, not uncaught exceptions. Use `notFound()` only when the requested resource does not exist and provide the appropriate `not-found.tsx` UI.

```tsx
import { notFound } from 'next/navigation'

export default async function Page({ params }: PageProps<'/posts/[id]'>) {
  const { id } = await params
  const post = await getPost(id)

  if (!post) notFound()

  return <article>{post.title}</article>
}
```
