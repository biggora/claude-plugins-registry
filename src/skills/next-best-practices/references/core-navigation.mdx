# Navigation and Prefetching

Use `<Link>` from `next/link` for ordinary internal navigation and `useRouter` from `next/navigation` for navigation triggered by non-link interactions. Do not replace a semantic link with a button plus `router.push()`.

## Read the Configuration First

`<Link>` prefetch behavior depends on the project mode:

| Mode | Default link behavior |
|------|-----------------------|
| Cache Components off | Static routes are fully prefetched. Dynamic routes are skipped or partially prefetched when a `loading.tsx` boundary exists. |
| `cacheComponents: true` | The cached page render is prefetched. A legacy `prefetch={true}` may also request dynamic content. |
| `cacheComponents: true`, `partialPrefetching: true` | Every link loads one reusable App Shell per route. URL-specific content streams after navigation unless a link intentionally uses `prefetch={true}`. |

In Next.js 16.3, small prefetch responses are inlined automatically to reduce request count while large shared segments remain separately reusable. Do not add `experimental.prefetchInlining` unless measurements or debugging justify changing the default.

## Partial Prefetching

Partial Prefetching is separate from Cache Components and requires it:

```ts
import type { NextConfig } from 'next'

const nextConfig: NextConfig = {
  cacheComponents: true,
  partialPrefetching: true,
}

export default nextConfig
```

The App Shell contains route output that does not depend on a link's URL. It is reused by links to different dynamic URLs for the same route. Reads of `params` and `searchParams` are URL-specific; place them in a child behind `<Suspense>` so the rest of the route can remain in the shell.

```tsx
import { Suspense } from 'react'

export default function Page({ params }: PageProps<'/products/[slug]'>) {
  return (
    <ProductLayout>
      <Suspense fallback={<DetailsSkeleton />}>
        <ProductDetails params={params} />
      </Suspense>
    </ProductLayout>
  )
}

async function ProductDetails({
  params,
}: Pick<PageProps<'/products/[slug]'>, 'params'>) {
  const { slug } = await params
  return <Details product={await getProduct(slug)} />
}
```

Audit every existing `<Link prefetch={true}>` before enabling Partial Prefetching:

- Remove it when the destination is static or already part of the App Shell.
- Keep it when deliberately prefetching cached URL-specific content.
- Remove it for real-time request data that would be stale by click time.
- Keep `prefetch={false}` when prefetching is intentionally disabled.

Per-link URL-data prefetching costs a server invocation for each prefetchable link. Use it selectively, not as a blanket performance fix.

## Making Navigation Instant

An instant route must have meaningful UI ready at click time. Provide that UI by:

- caching stable work with `'use cache'`, or
- moving request-time work behind `<Suspense>` with a useful fallback.

With Cache Components enabled, development diagnostics offer three explicit trade-offs:

- **stream** — add a Suspense boundary and show fallback UI immediately;
- **cache** — cache the work when sharing or staleness is acceptable;
- **block** — export `const instant = false` when the route is intentionally allowed to wait.

`instant = false` is an adoption escape hatch, not a performance improvement and not a replacement for dynamic rendering configuration.

## Programmatic Navigation

```tsx
'use client'

import { useRouter } from 'next/navigation'

export function SaveButton() {
  const router = useRouter()

  return <button onClick={() => router.replace('/dashboard')}>Done</button>
}
```

Available methods include `push`, `replace`, `back`, `forward`, `refresh`, and `prefetch`. Never pass untrusted or unsanitized URLs to `push` or `replace`; `javascript:` URLs execute in page context.

## Verification

Prefetching is disabled in development, so a normal dev navigation does not prove the production shell is ready. Use the Next.js Navigation Inspector to pause at the shell, and use `instant()` from `@next/playwright` for a regression test when click-time UI matters:

```ts
import { expect, test } from '@playwright/test'
import { instant } from '@next/playwright'

test('product shell is ready at click time', async ({ page }) => {
  await page.goto('/products/shoes')

  await instant(page, async () => {
    await page.click('a[href="/products/hats"]')
    await expect(page.getByRole('heading', { level: 1 })).toHaveText('Hats')
    await expect(page.getByText('Checking inventory...')).toBeVisible()
  })
})
```
