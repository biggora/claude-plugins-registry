# Server Actions

Server Actions are async functions that run on the server. They can be called from the client through network requests. When used for mutations (forms, buttons), they're called Server Actions.

## Creating Server Actions

Add the `"use server"` directive to mark a function as a Server Action:

```ts
// app/lib/actions.ts
'use server'

export async function createPost(formData: FormData) {
  const session = await requireUser()
  const input = parsePost(formData)

  await db.post.create({
    data: { ...input, authorId: session.user.id },
  })

  // Revalidate cache
  revalidatePath('/posts')
}
```

Or add the directive to individual functions:

```ts
export async function createPost(formData: FormData) {
  'use server'
  // ...
}

export async function deletePost(formData: FormData) {
  'use server'
  // ...
}
```

## Inline Server Actions

Define Server Actions directly in Server Components:

```tsx
// app/page.tsx
export default function Page() {
  async function createPost(formData: FormData) {
    'use server'
    // ...
  }

  return <form action={createPost}>{/* ... */}</form>
}
```

## Treat Every Action as an Untrusted Entry Point

A Server Action is reachable as a POST request by anyone who can reproduce the request. Hiding a button or gating the page render is not authorization. Inside every action:

1. Authenticate the caller.
2. Authorize the operation against the target resource.
3. Validate `FormData` and every client-controlled argument.
4. Re-read ownership and trusted fields from the server; do not accept a whole database record from the client.
5. Return only the data the UI needs, because action results are serialized to the client.

```ts
'use server'

export async function deletePost(postId: string) {
  const session = await requireUser()
  if (!(await canDeletePost(session.user.id, postId))) {
    throw new Error('Forbidden')
  }

  await db.post.delete({ where: { id: postId } })
}
```

Next.js supplies CSRF origin checks, action-body limits, action-ID encryption, and closure encryption, but those framework protections do not replace application-level authorization. Self-hosted multi-instance deployments must use a stable `NEXT_SERVER_ACTIONS_ENCRYPTION_KEY` shared by all instances.

## Using Server Actions in Forms

Pass Server Actions to form `action` prop:

```tsx
// app/ui/form.tsx
import { createPost } from '@/app/actions'

export function Form() {
  return (
    <form action={createPost}>
      <input type="text" name="title" />
      <input type="text" name="content" />
      <button type="submit">Create</button>
    </form>
  )
}
```

```ts
// app/actions.ts
'use server'

export async function createPost(formData: FormData) {
  const session = await requireUser()
  const input = parsePost(formData)

  await db.post.create({
    data: { ...input, authorId: session.user.id },
  })
  revalidatePath('/posts')
}
```

## Using Server Actions in Buttons

Use `formAction` prop on buttons:

```tsx
'use client'

import { deletePost } from './actions'

export function DeleteButton({ id }: { id: string }) {
  const deletePostWithId = deletePost.bind(null, id)

  return (
    <form>
      <button formAction={deletePostWithId}>Delete</button>
    </form>
  )
}
```

## Using Server Actions in Event Handlers

Invoke Server Actions from Client Component event handlers:

```tsx
'use client'

import { incrementLike } from './actions'
import { useState } from 'react'

export function LikeButton({ initialLikes }: { initialLikes: number }) {
  const [likes, setLikes] = useState(initialLikes)

  return (
    <button
      onClick={async () => {
        const updatedLikes = await incrementLike()
        setLikes(updatedLikes)
      }}
    >
      Like ({likes})
    </button>
  )
}
```

## Pending States

Use `useActionState` to show loading states:

```tsx
'use client'

import { useActionState } from 'react'
import { createPost } from './actions'

export function Form() {
  const [state, formAction, pending] = useActionState(createPost, null)

  return (
    <form action={formAction}>
      <input type="text" name="title" disabled={pending} />
      <button type="submit" disabled={pending}>
        {pending ? 'Creating...' : 'Create'}
      </button>
      {state?.error && <p>{state.error}</p>}
    </form>
  )
}
```

## Optimistic Updates

Use `useOptimistic` for optimistic UI updates:

```tsx
'use client'

import { useOptimistic } from 'react'
import { updatePost } from './actions'

export function Post({ post }: { post: Post }) {
  const [optimisticPost, addOptimisticPost] = useOptimistic(
    post,
    (state, newPost: Post) => ({ ...state, ...newPost })
  )

  async function handleUpdate(formData: FormData) {
    addOptimisticPost({ title: formData.get('title') as string })
    await updatePost(formData)
  }

  return (
    <form action={handleUpdate}>
      <input name="title" defaultValue={optimisticPost.title} />
      <button type="submit">Update</button>
    </form>
  )
}
```

## Error Handling

Model expected failures such as validation and rejected input as return values for `useActionState`. Reserve thrown errors for unexpected failures or authorization boundaries that should be handled by an error boundary.

```ts
'use server'

export async function createPost(
  _previousState: { error?: string },
  formData: FormData
) {
  const session = await requireUser()
  const title = formData.get('title')

  if (typeof title !== 'string' || title.trim() === '') {
    return { error: 'Title is required' }
  }

  await db.post.create({
    data: { title, authorId: session.user.id },
  })

  revalidatePath('/posts')
  return {}
}
```

## Redirecting

Use `redirect` to navigate after mutations:

```ts
'use server'

import { redirect } from 'next/navigation'

export async function createPost(formData: FormData) {
  const session = await requireUser()
  const input = parsePost(formData)
  const post = await db.post.create({
    data: { ...input, authorId: session.user.id },
  })

  redirect(`/posts/${post.id}`)
}
```

`redirect()` throws a framework control-flow exception. Call revalidation APIs before it and do not place it inside a broad `try`/`catch` that would swallow the redirect.

## Revalidating Cache

Revalidate cache after mutations:

```ts
'use server'

import { revalidatePath, revalidateTag } from 'next/cache'

export async function updatePost(id: string, formData: FormData) {
  const session = await requireUser()
  if (!(await canEditPost(session.user.id, id))) {
    throw new Error('Forbidden')
  }

  const input = parsePostUpdate(formData)
  await db.post.update({
    where: { id },
    data: input,
  })

  // Revalidate specific path
  revalidatePath(`/posts/${id}`)

  // Or revalidate by tag
  revalidateTag('posts', 'max')
}
```

## Key Points

- Server Actions are async functions with `"use server"` directive
- Treat every action as an untrusted POST entry point; authenticate, authorize, and validate inside it
- Can be used in forms (`action` prop) and buttons (`formAction` prop)
- Can be invoked from event handlers in Client Components
- Use `useActionState` for pending states
- Use `useOptimistic` for optimistic updates
- Handle errors and return appropriate responses
- Use `redirect` to navigate after mutations
- Revalidate cache with `revalidatePath` or `revalidateTag`
- Server Actions use POST method and are called sequentially
